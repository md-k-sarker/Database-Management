01What you are installing

This module gets a working MySQL server and a client on your own computer, proves that they work, and shows you where everything else in the course lives. Plan on 30 to 45 minutes. Do it before Module 1.

Why 8.4 LTS?

  • LTS means long-term support: the 8.4 series receives bug and security fixes without feature changes, so what you learn this term stays true.
  • Oracle also publishes Innovation releases (the 9.x series) that change faster. The download page may show one of them first. Choose 8.4 instead.
  • MySQL 8.0 reached end of life in April 2026. Some operating systems still ship it as their default package, so check the version before you trust a package manager.

Client and server are separate

The server and the client are different programs. The server runs in the background and listens on a network port (3306 by default). Workbench and the mysql command are clients that connect to that port and send SQL. This is the client/server architecture from Module 1. When something fails, the first question is always: is the server running, and is my client pointed at the right place?

03Connect

Before using Workbench, try the plain command line client. If it connects, the server side is fine, and any later Workbench problem is about Workbench's settings.

Step 1. Connect from a terminal

Terminal (Windows: open "MySQL 8.4 Command Line Client" or Command Prompt)
mysql -u root -p

Type your root password when asked (nothing appears as you type). You should land at a mysql> prompt. If the command is not found, the program's folder is not on your PATH; use the full path or the Start menu entry the installer created.

Step 2. Connect from Workbench (not run here)

  1. Open Workbench. On the home screen, click the + next to MySQL Connections.
  2. Name it (for example COSC431 local). Leave the method as Standard (TCP/IP).
  3. Hostname 127.0.0.1 (your own computer), Port 3306, Username root. If the installer used another port, use that.
  4. Click Test Connection, enter the password, and look for a success message. Then click OK.
  5. Double-click the new connection tile. A SQL editor tab opens.

The Workbench editor in four facts

  • Type SQL in the large editor. Execute the current statement with Ctrl+Enter (Cmd+Enter on a Mac). Execute everything with Ctrl+Shift+Enter.
  • Results appear in a grid under the editor, with an output log below it showing success or the error.
  • The Schemas panel on the left does not refresh by itself after you create a database. Use its refresh button.
  • Workbench starts with safe update mode on. It blocks an UPDATE or DELETE that has no key column in its WHERE. That is Error 1175, shown in the last section of this page.

04Verify your environment

This is the module's learning outcome: create a test database, run a query, and clean up. The script below was run on a brand-new MySQL 8.4.2 server, so the results are exactly what a fresh install shows. Run the same lines in Workbench or the mysql client.

The verification script

SQL: run this on your machine
SELECT VERSION();
SHOW DATABASES;
CREATE DATABASE setup_check;
USE setup_check;
CREATE TABLE hello (id INT PRIMARY KEY, message VARCHAR(40));
INSERT INTO hello VALUES (1, 'My MySQL server works');
SELECT * FROM hello;
SHOW DATABASES;
DROP DATABASE setup_check;

What to look for

  • SELECT VERSION() returns a number beginning with 8.4. Your patch number (the last part) may be higher than 8.4.2.
  • The first SHOW DATABASES lists exactly four built-in databases on a fresh install: information_schema, mysql, performance_schema and sys. If you have used the server before, you will see more.
  • After CREATE DATABASE, the list gains setup_check. After DROP DATABASE it is gone again.
  • The table query returns one row with the message you inserted.

05When something goes wrong

Most setup problems are one of about ten errors. Each message below was produced by a real MySQL 8.4.2 server by doing the thing that causes it. Pick a message, or paste one from Workbench or the terminal, and the diagnostic explains what it means and what to try.

The ten errors at a glance

ErrorSQLSTATEMeaning
2003HY000Can't connect to MySQL server
104528000Access denied for user
104942000Unknown database
104442000Access denied to database
10463D000No database selected
114642S02Table doesn't exist
106442000You have an error in your SQL syntax
1007HY000Can't create database; database exists
1175HY000Safe update mode
1524HY000Plugin 'mysql_native_password' is not loaded

Workbench shows the same errors as Error Code: 1146. Table ... doesn't exist in its output panel. The number is what matters.

A general method

  1. Read the number and the message. Search the manual for the number if you do not know it.
  2. Decide which side failed: cannot connect (2xxx numbers, 1045) is about the server, host, port or login; everything else is about the statement you sent.
  3. Check the basics: is the server running, which database is selected, did you spell the names correctly?
  4. Change one thing at a time and run again.
