01What is a database?

A database is an organized collection of related data. A database management system (DBMS) is the software that stores, protects and serves that data to many users and programs at once. Together with the applications that use them, they form a database system.

Three words that are easy to mix up

TermMeaningExample
DatabaseThe data itself, organized so it can be found, shared and kept correct.The customer and purchase tables of a shop
DBMSGeneral-purpose software that creates, stores, queries and protects databases.MySQL, PostgreSQL, SQLite, MongoDB
Database systemThe database + the DBMS + the application programs and people that use them.The shop's website, its MySQL server and its data
Data modelA set of concepts for describing the structure of the data.The relational model (tables, rows, keys)
Schema and instanceThe schema is the description of the structure and rules. The instance is the data stored at one moment.customer(customer_id, name, phone, city) is a schema; its current rows are an instance

A first look at a real one

The tutorial's demo database is a tiny shop with two tables. The statement below is run on a real MySQL server. You will meet the same data again in later sections.

SQL
SELECT c.name, c.city, p.item, p.qty FROM customer c JOIN purchase p ON p.customer_id = c.customer_id ORDER BY p.purchase_id;
Output (MySQL 8.4)
+------+--------------+----------+-----+
| name | city         | item     | qty |
+------+--------------+----------+-----+
| Ana  | Muncie       | Notebook |   3 |
| Ana  | Muncie       | Pencil   |  10 |
| Ben  | Indianapolis | Stapler  |   1 |
| Cara | Muncie       | Notebook |   2 |
| Cara | Muncie       | Marker   |   4 |
| Dev  | Fort Wayne   | Pencil   |   6 |

Notice what you did not have to say: where the files are, how rows are stored, which row to read first, or how to avoid two users clashing. You described what you wanted; the DBMS worked out how. That division of labour is the theme of this whole module.

02Files versus a DBMS

Before databases, each program kept its own files. That works until two programs need the same facts. This section shows exactly how it breaks, and how a DBMS avoids it.

The scenario

A shop has three programs: Sales, Billing and Support. Each needs the customers' phone numbers. In the file approach, each program keeps its own copy in its own file. In the database approach, there is one copy that all three read.

Simulator

Pick a way of storing the data, choose which program learns the new phone number, and press Save. Then look at what each program believes about Ana.

What really happened (recorded)

The same experiment was run for real. First with three CSV files, where the Sales program updated only its own file:

Result with three files (Python 3, csv module)
sales.csv    Ana -> 555-0999
billing.csv  Ana -> 555-0101
support.csv  Ana -> 555-0101

Then with a MySQL database, where the three programs read one table through three views. One UPDATE was enough:

SQL
UPDATE customer SET phone = '555-0999' WHERE name = 'Ana';
Output (MySQL 8.4)
Query OK, 1 row affected
Rows matched: 1  Changed: 1  Warnings: 0
SQL
SELECT 'sales' AS app, name, phone FROM v_sales WHERE name = 'Ana'
UNION ALL SELECT 'billing', name, phone FROM v_billing WHERE name = 'Ana'
UNION ALL SELECT 'support', name, phone FROM v_support WHERE name = 'Ana';
Output (MySQL 8.4)
+---------+------+----------+
| app     | name | phone    |
+---------+------+----------+
| sales   | Ana  | 555-0999 |
| billing | Ana  | 555-0999 |
| support | Ana  | 555-0999 |
+---------+------+----------+
3 rows in set

Problems of the file-based approach

ProblemWhat it looks likeHow a DBMS addresses it
RedundancyThe same fact is stored in many files, wasting space and effort.Store each fact once and share it; design with normalization (Module 7)
InconsistencyThe copies disagree, as Ana's phone number did above.One copy, plus integrity constraints
Program-data dependenceThe file layout is written into every program. Adding a column means rewriting them all.The DBMS stores the description of the data; programs ask by name
Hard to ask new questionsEach new question needs a new program.A query language (SQL) answers new questions without new programs
No concurrency controlTwo programs writing the same file can overwrite each other.Transactions and locking (Module 10)
Weak securityFile permissions are all-or-nothing for a whole file.Accounts and privileges down to tables and columns (Module 10)
No recoveryA crash in the middle of a write can leave a damaged file.Logging and recovery restore a consistent state

03What a DBMS provides

A DBMS is not just a place to put data. It provides a set of services that every serious application would otherwise have to build for itself.

What a DBMS provides

ServiceIn one sentenceWhere this course covers it
Self-describing dataThe structure of the database is stored in the database, in the catalog (data dictionary).Section 5, and Module 2
Program-data and operation independencePrograms do not depend on how data is stored.Section 4
Multiple viewsDifferent users see different parts and arrangements of the same data.Section 4 and Module 4 (views)
Data sharing with concurrency controlMany users work at once without damaging each other's work.Module 10
Integrity constraintsThe database refuses data that breaks the rules.Module 2
Security and authorizationOnly permitted users do permitted things.Module 10
Efficient query processingIndexes and an optimizer find data fast.Modules 3 and 9
Backup and recoveryAfter a failure the database returns to a consistent state.Module 10

The database describes itself

One property deserves a demonstration. In MySQL, the tables, columns and keys are themselves data you can query, through the schema information_schema. Here is the server describing one of our tables:

SQL
SELECT column_name, data_type, is_nullable, column_key
FROM information_schema.columns
WHERE table_schema = 'm1_demo' AND table_name = 'customer'
ORDER BY ordinal_position;
Output (MySQL 8.4)
+-------------+-----------+-------------+------------+
| COLUMN_NAME | DATA_TYPE | IS_NULLABLE | COLUMN_KEY |
+-------------+-----------+-------------+------------+
| customer_id | int       | NO          | PRI        |
| name        | varchar   | NO          |            |
| phone       | varchar   | NO          |            |
| city        | varchar   | NO          |            |
+-------------+-----------+-------------+------------+
4 rows in set

When a DBMS is not the right tool

A DBMS has costs: it is more software to install and learn, it needs memory and administration, and its generality adds overhead. Plain files or a simple library can be better when:

  • the data is small, simple and unlikely to change, and only one program uses it;
  • the program has hard real-time requirements that the DBMS overhead cannot meet;
  • there is no need for several users to access the data at once.

The last section of this tutorial lets you practise making that call.

04Data models and three schemas

A DBMS describes data at several levels, so that a change at one level does not break the levels above. This idea is called the three-schema architecture (from the ANSI/SPARC proposals of the 1970s).

The three levels

LevelSchemaDescribesWho caresIn MySQL
ExternalExternal schemas (user views)The part of the data one group of users needs, in the form they need itApplication developers, end usersViews, and the privileges on tables and columns
ConceptualConceptual schemaAll entities, attributes, relationships and constraints of the whole database, with no storage detailDatabase designersThe tables, keys and constraints
InternalInternal schemaHow data is physically stored: files, pages, indexes, access pathsDBAs, the DBMS itselfStorage engine (InnoDB), indexes, tablespaces

Data independence

  • Logical data independence: change the conceptual schema (add a column, split a table) without changing the external schemas or application programs.
  • Physical data independence: change the internal schema (add an index, move files, change the storage layout) without changing the conceptual schema or the programs.

Physical independence is almost complete in practice. Logical independence is harder: it works as long as the DBMS can still present the old shape to the program, here by rewriting a view.

Watch independence happen

The stepper below replays a real MySQL session. An application runs one query through a view. Then we change the physical level and the logical level underneath it, and run the same query again.

Be honest about the limits

Views give logical independence only up to a point. A view over a join can usually be read, but writing through it is restricted in MySQL, so programs that change data may still need updating after a big redesign. Independence is a goal that the design supports, not a guarantee.

05Inside a DBMS

What happens between typing a query and getting rows back? Click each box to follow a statement through a MySQL 8.4 server. The outputs under each box were produced by a real server.

Two layers worth remembering

  • The SQL layer (connection handling, parser, optimizer, executor) is the same whichever way the data is stored.
  • The storage engine layer actually stores and fetches rows. MySQL lets different tables use different engines. InnoDB is the default and the one used in this course because it supports transactions and foreign keys.
Not only MySQL

Other systems are organized differently in the details, but they all have equivalents of the same jobs: parse, optimize, execute, cache pages, lock, log and keep a catalog.

06People and languages

Different people touch a database in different ways, and SQL has different groups of statements for them.

People

RoleJob
Database administrator (DBA)Installs and tunes the DBMS, creates accounts, manages backups, security and performance.
Database designerDecides what data to store and how to structure it (Modules 2, 6 and 7).
Application developerWrites programs that send SQL to the database (Module 8).
End userUses applications or reports; casual users may run queries directly.
Data analyst / data scientistQueries and summarizes data to answer questions.

Groups of SQL statements

SQL statements are often grouped by purpose. Textbooks differ slightly on the groupings, but these are the common ones:

GroupPurposeStatements
DDL data definitionDefine or change the structureCREATE, ALTER, DROP
DML data manipulationChange the dataINSERT, UPDATE, DELETE
DQL data queryRead the data (sometimes counted inside DML)SELECT
DCL data controlControl accessGRANT, REVOKE, CREATE USER
TCL transaction controlGroup statements into transactionsSTART TRANSACTION, COMMIT, ROLLBACK

07System environments

Where the DBMS runs relative to its users is another architectural choice.

ArchitectureHow it worksExample
Embedded (serverless)The DBMS is a library inside the application and reads a file directly. No separate server process.SQLite in a phone app. Its in-browser build powers the practice labs in this course.
Client/server, two-tierClient programs connect directly to a database server over the network.MySQL Workbench or the mysql client connected to a MySQL server
Three-tierClient (browser) talks to an application server, which talks to the database server. Users never reach the database.A typical web application (Module 8)
Distributed / replicatedData is spread over or copied to several servers for capacity and availability.MySQL replication; many NoSQL systems (Module 5)
Managed cloud serviceThe provider runs the servers, backups and updates. You connect as a client.Hosted MySQL or PostgreSQL offerings

The three-tier layout matters for security: the database server is not exposed to the internet, only the application server is. You will see the code for the middle tier in the database connectivity tutorial.

08The design lifecycle

Databases are designed, not just created. The usual path goes from what users need, through a design that has nothing to do with any product, down to tables, indexes and finally a running system. Real projects loop back as requirements change.

Textbooks name and group these phases slightly differently (some merge testing into implementation, some add a separate "data model mapping" step). The order and the ideas are what matter.
